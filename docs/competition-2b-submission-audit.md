# 方向 2B 提交差距审计与完善方案

> 本文保留早期审计过程，其中的数据量和回归数字已经被后续实现取代。2026-08-24 的当前结论请以 [方向 2B 后端与数据最终说明](competition-2b-final-backend-and-data.md) 为准。

审计基线：`赛道一-方向2B-太阳物理假设生成与证据推理-提交要求及模板(1).docx`。本项目选择题目 2“日冕加热之谜”。本文件只陈述已经在代码、数据或真实运行中验证的能力；尚未完成的内容明确标为缺口。

## 1. 总体判断

当前系统已经具备 2B 要求的核心科学闭环：输入科学现象后，动态生成竞争假设，检索论文和本地观测，执行确定性 FITS 分析，构建支持/不支持记录，主动查找同活动区背景反例，形成下一步验证计划，并在证据不足时输出 `needs_data` 而不是伪造结论。后端现在分别报告“证据是否足以支持假设”和“闭环字段是否完整”，避免把科学未确证误写成流程失败。

当前最大风险已从“后端能否运行”转移到“提交包是否合规”。P3 和 P5 已有较强实现，P7 的 Python 锁定依赖、第三方许可证清单、标准化示例输出和一键核心命令已补齐。仍未完成的硬阻塞是：团队选定根目录许可证、处理两项 `Unknown` 第三方条目、公开仓库并固定不可变 Commit。

## 3. 真实 Qwen 基线结果

固定输入：NOAA AR11158 的 AIA 94/131 Å 间歇增强、171/193 Å 准周期变化和 HMI 视向磁场演化；比较波动耗散、纳耀斑重联、耦合机制及替代解释。

真实模型辅助运行 `run-1787228974299-f017d43d` 完成两轮 A—B—C—D：

- 3 条动态候选假设；机制贡献比例全部被系统移除，因为现有数据没有能量分配依据。
- 32 条证据/审查记录，其中 10 条带确定性处理 provenance，5 条带数量区间，2 条被标为“支持一项非唯一预测”。
- 带 provenance 的记录实际只来自 1 个原始数据指纹和 1 个目标事件组，不能被重复运行伪装为独立证据。
- 12 项验证任务，其中 3 项在第二轮完成，9 项保留为计划；没有执行器的任务没有被伪装成已完成。
- 最终运行状态为 `completed`，科学状态为 `needs_data`，终止原因为 `max_rounds_reached`。
- 模型辅助两轮总耗时 855.7 秒（约 14.3 分钟），11 次 Qwen 角色调用，工具输入/输出错误为 0。本地 FITS 处理使用 CPU；本地 GPU 不是必需条件。

这是一份合格的“闭环成功、科学结论未确证”案例。比赛模板要求候选假设、证据链、反例和验证计划，并没有要求系统必须证明某一机制。对小数据强行输出 `supported` 反而会降低科学可信度。

一键脚本也已实际执行 `local-grounded` 一轮冒烟测试：75.2 秒内完成服务健康检查、项目创建、SSE 请求、核心闭环和结果导出，返回 `needs_data`。

后端数据利用修复后，两轮本地闭环 `run-1787233694925-01ba3114` 已验证：第一轮使用 AR11158 目标 340/340 条和背景 190/190 条逻辑观测，第二轮由登记执行器选择 AR11429 作为冻结参数的跨活动区 holdout，并使用 190/190 条逻辑观测；holdout 任务完成并生成独立快照、处理产物和 lineage。热通道间歇性预测在两个目标事件中得到带区间的同方向记录，但状态仍为 `uncertain`；波动与耦合候选在留出事件中没有满足预设条件，保持 `candidate`，没有被强行升级。

新契约也已用本机真实 Qwen 回归：`run-1787233951522-0271cc60` 在 768.1 秒内完成两轮，生成 4 条动态假设、39 条记录，其中 11 条带确定性 provenance；全部模型和确定性证据角色均完成。第二轮同样执行 AR11429 holdout，纳耀斑第一条原子预测形成两个独立事件的有效支持记录，但其他预测、观测量族和方法族未补齐，最终仍为 `needs_data`。该回归还暴露出 planner 会再次计划已尝试的同一 holdout；后端随后增加“假设 + 预测 + holdout 已尝试”过滤。提交前仍应基于冻结 Commit 再导出最终 Qwen 示例。

## 4. 数据量是否足够

官方模板没有规定最低 GB、文件数或论文数。合理数据量应由待验证命题和证据独立性决定，而不是由磁盘体积决定。

当前约 7.374 GB 数据足以完成以下目标：

- 演示自然语言现象到候选假设、真实 FITS 指标、反例和验证计划的完整闭环；
- 对一个目标窗口执行 AIA 171/193 时序、94/131 热通道变异和同活动区背景比较；
- 在 AR11429 上以冻结流程复测可由现有代理量检验的原子预测，形成真实 holdout，而不是重复处理 AR11158；
- 暴露短时间窗、自动 ROI、近似配准和诊断非唯一性等真实限制。

当前数据不足以完成以下主张：

- 证明波动耗散、纳耀斑重联或耦合机制在日冕加热中占主导；
- 推断能量贡献比例或因果耦合；
- 用两个目标事件建立跨活动区普遍规律；
- 完成光谱非热展宽、DEM、传播速度、能量闭合或 MHD 前向模拟验证。

系统的严格支持门槛要求至少 3 个可审计支持记录、3 个独立事件组、3 个独立原始数据谱系、2 个观测量族、2 个方法族、至少一个有效 holdout 支持，并覆盖假设的全部预测且置信度不低于 0.60。当前热通道间歇性只达到 2 个独立目标事件和 1 个方法/观测量族；冷却时延、磁结构统计关联等预测仍未覆盖。因此当前数据可以做比赛 Demo，但不能跨越这些条件宣称机制被证实。

新增数据采用“任务触发”而不是“先堆容量”的策略：先用现有六个 AIA 波段和 HMI 文件实现多通道冷却时延、事件目录、WCS 配准质量审计等尚未落地的诊断；只有某条高优先级预测在这些处理后仍因独立事件数不足而阻塞，才下载第三个目标事件。光谱、矢量磁场或 MHD 数据只在对应验证任务进入高优先级且现有代理量无法区分时补充。后端的 `dataReadiness.requiresNewData` 与任务级 `readiness/blockedReason` 会明确给出这一判断，不能再仅凭总 GB 数宣称“数据不足”。

预处理不会把原始数据需求“消失”。当前处理在每条流不超过 96 帧时使用全部登记帧，并把 4096×4096 FITS 转成按内容寻址的 256 级轻量帧以复用。实测 AR11429 的 190 个原始文件共 1.8748656 GB，对应派生缓存约 14.14 MB（约 0.754%）；完整 704 文件缓存约 58.16 MB（约 0.789%）。两者用途不同，原始 FITS 必须保留。若在 9.3 GB 总预算内新增一个与 AR11429 同规格的完整六波段 + HMI 窗口，总量约 9.249 GB，余量只有约 51 MB，不稳妥。更合理的最小补数是一个独立目标事件的 94/131/171/193 Å + HMI，按当前案例约 1.384 GB，使总量约 8.758 GB；若能使用活动区裁剪产品还可进一步降低体积。

## 5. 可提交的创新点

1. **模型与证据分权**：Qwen 负责提出、解释和规划；只有确定性处理产物可成为 support/contradict 证据。
2. **独立性而非记录数**：按事件组和原始数据指纹去重，重复运行、换代理或换提示词不能虚增证据强度。
3. **预测级证据绑定**：证据和验证任务绑定稳定的 prediction/falsification ID，而不是只挂在整条假设上。
4. **反例优先闭环**：同活动区背景对照和反证审计智能体主动寻找诊断非特异性，不只累积支持材料。
5. **执行器能力契约**：模型只能选择已登记的诊断契约；WCS、DEM、磁场相关、MHD 等未实现能力必须标记为 external。
6. **有边界停止**：达到轮次上限或缺少独立证据时输出 `needs_data`/`blocked`，不把流程完成误写成科学问题收敛。
7. **全链路可审计**：输入摘要、数据快照、文件校验和、处理运行、产物 ID、模型角色、任务和结论均可追踪。
8. **缓存不冒充新证据**：轻量派生帧只减少重复 FITS 解码；事件独立性仍由原始 manifest、案例和数据指纹确定。
9. **逐假设验证报告**：机器可读报告同时区分“留出已执行”和“留出形成有效支持”，并列出预测覆盖、证据门槛失败原因和下一步动作。
10. **证据门槛与闭环完整度分离**：`scientificStatus` 判断科学结论，`closureStatus` 判断假设—证据/反例—判定—计划是否完整；`uncertain` 也可形成诚实、可提交的闭环。
11. **任务级数据决策**：每项计划记录所需数据/设施、执行就绪度、预期周期、成功与失败判据；只有 `requires_data` 任务才进入补数清单。

## 6. Demo 设计

### 6.1 成功案例

输入 AR11158 多波段现象，展示三条竞争候选；展示真实 FITS 指标及区间；展示背景反例和缺失诊断；最终输出 `needs_data` 及下一步任务。成功标准是“完成可信推理闭环”，不是“选中一个机制”。

### 6.2 失败/局限案例

- **结构化提交失败**：Qwen 曾把整个 JSON 对象打包进 `hypotheses` 字符串，导致 A 阶段得到空候选。兼容层现在只在完整字符串能被严格解析为 JSON 时恢复字段，并有真实回归用例。
- **执行器错配**：模型曾把 94/131→171/193 冷却时延交给只支持 171/193 的执行器。新协议改为固定 diagnosticId，由后端生成执行范围并精确绑定预测，已完成任务也不会重复执行。
- **不稳定区间**：目标/背景比的 bootstrap 分母接近零时会产生无意义的巨大上界。系统现在不发布该区间，也不让它进入支持门槛，而是保留为数据局限。

## 7. 提交前优先级

### P0：不完成就不应提交

1. 团队确认并添加根目录 `LICENSE`，将 README 的 `Private` 改为真实许可证；不得由工具替团队决定权利许可。
2. 人工核验 `third_party_licenses.md` 中两个 `Unknown` yuku 二进制包，并声明 Qwen API 和 JSOC 数据条款。
3. 建立公开仓库，记录不可变 Commit Hash，再用干净环境执行一键 Demo 做最终验收。

### P1：显著影响专家评分

1. 将 P5 按逐假设“预测—证据—反例—状态—下一步”组织，而不是堆叠智能体日志。
2. 提供一张架构图、一张真实诊断图和一张证据链示意，所有图标出数据边界。
3. 将主参考文献、数据来源、模型/API 和处理工具整理为 P2/P4 表格。
4. 完成成功与局限案例的现场演示脚本。

### P2：扩展项

1. 在现有 AR11429 holdout 之外增加第三个独立目标活动区，提升可验证性，而不是只扩大同一窗口文件数。
2. 新增 WCS 配准、DEM/光谱、传播速度或 MHD 执行器后，再考虑提高机制支持等级。
