# Qwen3.5-Plus 科学闭环实跑审计（2026-08-21）

## 1. 结论

本次使用项目现有配置中的真实 `qwen3.5-plus` API 连续完成了四次科学流水线运行。结果表明：当前系统已经具备“提出多个竞争假设—检索和处理数据—寻找反例—规划后续验证—给出有界结论”的框架，也能在对抗性输入下拒绝强行证明某个机制；但目前还不足以形成比赛提交所需的严谨证据闭环。

当前首要瓶颈不是原始数据的 GB 数，而是：

1. 已有 704 个原始资产只产生了 3 类定量指标，AIA 211/335 Å 和 HMI 数据几乎没有进入证据门；
2. 实际指标与假设预测之间缺少机器可检查的语义约束，存在错误绑定和假覆盖；
3. 不同轮次、不同活动区的数据状态会在模型上下文中混用；
4. 纠错记录能够指出错误，但不会改变证据的有效状态；
5. 结构化结论门控较严格，但自然语言结论仍可能在“无有效支持证据”时暗示某机制更优。

因此，应先修复证据合同、上下文隔离和关键分析算子，再决定补多少数据。只增加数据不会自动提高严谨性，反而会批量放大当前的错误绑定。

## 3. 已经做对的部分

1. **假设具有动态性。** 开放式运行生成了热非平衡循环这一有效替代机制；受约束运行则稳定生成波动、纳耀斑和耦合三类机制。
2. **支持门槛明显高于简单投票。** 所有运行都没有把任一机制错误升级为 `supported`；门槛检查了支持记录数、独立事件、独立原始 lineage、可观测量家族、方法家族、留出证据、预测覆盖和置信度。
3. **留出数据确实被执行。** 修正后的运行在第二轮处理了 AR11429，而不是简单复制 AR11158 的原始 lineage。
4. **反例角色有效。** Oracle 多次指出单一强度变异不是机制唯一诊断，并发现了活动区混淆和溯源不足。
5. **对抗性安全边界基本有效。** 即使提示要求给出唯一机制，结构化输出仍保持 `inconclusive`，没有伪造支持证据。
6. **置信度依据已有结构。** `confidenceBasis` 已记录模型、文献、统计和留出更新过程；真正的问题是更新所依赖的证据可能绑定错误，而不是字段为空。

## 4. P0：补数据前必须修复

### P0-1 指标—预测语义绑定错误

修正运行中的纳耀斑假设有两条关键预测：

1. 94/131 Å 出现局域间歇热事件；
2. 94/131 Å 峰值先于 171/193 Å，冷却时滞为 5–15 分钟。

第一轮的热通道变异度与峰数被绑定到预测 1，尚可作为非唯一的一致性指标。第二轮留出执行器仍只返回热通道变异度 `0.271` 和 2 个峰，没有计算任何热到冷时滞，却被绑定到预测 2 并记为 `support`。这使验证报告错误地声称已经覆盖两条预测。

根因在 [default-services.ts](../packages/agents/src/scientific-loop/default-services.ts)：执行器按任务传入的 `predictionIds` 写回证据，而不是按实际产出的指标能力决定可绑定预测。留出任务也宣称能检查传播速度和冷却时滞，但现有执行器只会计算积分 ROI 的周期/相关和热通道变异。

修复方案：

- 将预测从自由文本改为结构化合同：`observable`、`operator`、`threshold`、`unit`、`window`、`cadenceRequirement`、`spatialRequirement`、`sourceIds`、`falsifier`、`requiredCapabilities`。
- 每个执行器声明 `producedCapabilities` 和 `producedMetrics`；证据绑定取“预测需求 ∩ 执行器能力”，任务给出的 ID 只能限定范围，不能覆盖能力检查。
- 不能测量冷却时滞的执行器必须返回 `unsupported_metric` 或 `unknown`，不得把热通道峰数映射到冷却时滞。
- 将“与某条预测一致”和“支持某个机制”分开表示，非唯一代理量不得单独升级机制。

验收标准：使用同一修正请求重跑时，现有热通道变异执行器不得覆盖纳耀斑预测 2；只有真正输出 `hot_to_cool_lag_seconds` 及区间的执行器才能绑定该预测。

### P0-2 纠错只记录、不执行

修正运行产生了 28 条 corrections，其中两条 `error` 明确要求：

- 将第一轮纳耀斑 `support` 降级，因为热通道间歇性不是唯一诊断；
- 将跨活动区且无确定性溯源的记录降级为 `unknown`。

但最终验证报告仍把被纠错的发现证据列入 `validSupportEvidenceIds`。这说明纠错目前是旁路说明，不是裁决层。

修复方案：

- 新增 `EvidenceAdjudication` 或 `effectiveStatus`，保留原始记录不可变，同时由裁决层计算最终有效状态。
- `error` 级纠错对指定证据执行 veto；`warning` 降低权重或要求人工复核。
- 证据门、置信度更新、结论和闭环报告全部只读取有效状态。
- 对重复 corrections 进行语义去重，但不能把去重放在执行纠错之前。

验收标准：任何被 `error` correction 撤销的记录不得出现在 `validSupportEvidenceIds`，也不得提高置信度。

### P0-3 跨轮次、跨事件上下文污染

修正运行第二轮的确定性处理值属于 AR11429：171/193 Å 候选周期为 7200/3600 秒、相关系数约 0.972，94/131 Å 相对变异度约 0.271。可是第二轮 Looker/Explorer 仍引用 AR11158 的 1800 秒、0.49、0.508 和 3.23；Oracle 则使用了正确的留出值。不同角色实际上没有看到同一个事件事实包。

[context-builder.ts](../packages/agents/src/scientific-loop/context-builder.ts) 当前主要按任务、假设和证据窗口投影上下文，再从证据中分别汇总 snapshot、artifact 和 processing run ID，无法保证事件身份和指标载荷原子一致。

修复方案：

- 引入原子 `EvidenceBundle`：`eventId`、`caseId`、`analysisSplit`、`processingRunId`、`rawFingerprint`、`metrics`、`cadence`、`window`、`artifacts`、`limitations`。
- 一个模型调用只能消费明确列出的 bundle；禁止从不同 bundle 拼接 `caseId` 与指标。
- 新处理完成后，失效同轮中与该任务相关的旧目录状态；每条模型证据必须回填所引用的 bundle ID。
- 增加跨事件污染测试：若文本引用 AR11158，却绑定 AR11429 processing run，schema 校验必须失败。

### P0-4 活动区输入路由不可靠

[coronal-data.ts](../packages/tools/src/coronal-data.ts) 通过清洗后的整段字符串做 `includes` 匹配。输入“NOAA 11158；holdout NOAA 11429”会被合并成一个无法匹配的 needle，最终把“数据存在但未匹配”误报成“数据缺失”。

修复方案：

- API 使用显式字段：`discoveryCaseId`、`backgroundCaseId`、`holdoutCaseIds`，活动区名称只作显示和后备搜索。
- 兼容自由文本时，用正则抽取全部 NOAA 编号并分别规范化，而不是合并字符串。
- 数据状态拆为 `data_absent`、`data_present_unmatched`、`executor_unavailable`、`derived_product_missing`、`data_quality_failed`。
- 只要 manifest 已验证且匹配失败，就不得生成“需要新增数据”的结论。

### P0-5 自然语言结论与结构化状态不一致

对抗运行中 18 条证据全部为 `unknown`，三个假设的 `validSupportEvidenceIds` 均为空，但结论仍称纳耀斑机制“具有相对较高的兼容性”。当前 [scientific-graph.ts](../packages/agents/src/scientific-loop/scientific-graph.ts) 的后置保护主要拦截“已证明、已证实、机制成立”等强词，无法拦截“更兼容、较优、可能主导”等软性越界。

修复方案：

- 结论先由验证报告确定允许陈述的事实，再让模型负责表述。
- `validSupportEvidenceIds` 为空时，禁止任何机制排序和“更兼容/更优/主导”表达。
- 输出必须逐条引用有效证据 ID；若模型文本与状态冲突，改用确定性模板并记录 correction。

验收标准：对抗请求只能得到“当前无法比较机制优先级；以下指标仅构成待验证线索”一类结论。

## 5. P1：现有数据应补齐的分析能力

应按以下顺序实现，前五项不要求新增原始观测：

1. **WCS、太阳自转和跨通道配准审计。** 在空间关系成立前，任何“沿环传播”“与 PIL 重合”“空间耦合”都只能是未验证任务。
2. **多通道热到冷时滞。** 对 94/131→335/211/193/171 Å 计算方向明确的时滞、块 bootstrap 区间和不同去趋势设置的稳健性。
3. **热事件目录。** 在 AR11158 的 24 秒 burst 和普通 240 秒窗口上分别做 cadence-aware 检测，输出峰值、持续时间、面积、空间连贯性、假发现率和背景对照。
4. **沿环时间—距离分析。** 使用环路径而非自动高变异矩形 ROI，输出传播方向、速度和不确定度；只有随后结合密度/速度代理量，才能讨论波动能流。
5. **HMI 代理量执行器。** 先对现有 LOS 数据计算无符号磁通、梯度、PIL 邻域和磁通变化，并明确它们不是矢量剪切或自由磁能。若要验证真正的剪切/自由能，再补 HMI 矢量场。
6. **波动—热事件耦合。** 采用预注册的事件触发平均、相位/时滞和保留自相关结构的 time-shift/permutation null；不能用普通相关系数证明因果耦合。
7. **DEM 与温度演化。** 在响应函数、曝光归一和误差传播齐备后执行；不得把通道强度直接等同于温度。
8. **稳健性与反例搜索。** 对去趋势窗口、ROI、背景区、阈值、时间窗做敏感性分析，使用 block bootstrap 和多重检验控制。

在完成事件检测的 completeness、曝光/响应、面积和能量标定之前，不应检验或宣称纳耀斑能量幂律指数及其总加热功率。

## 6. P1：内容分析和任务合同

### 6.1 数值阈值需要逐预测来源

Qwen 生成了 500–2000 km/s、2–10 分钟、5–15 分钟、1–5 Mm、幂律 1.5–2.5 等阈值。当前只有假设级 `sourceIds`，不能知道哪个来源支持哪一个阈值。

应要求每条 Prediction 自带来源和适用条件；无来源数值只能标为 `exploratory`，不能用于证伪或支持门。

### 6.2 先做可检测性检查

当前常规 171/193 Å cadence 为 240 秒，Nyquist 对应的最短周期约为 8 分钟，因此“2–10 分钟”只有一小段可检验，“1–5 分钟”在这些数据上不可检验。24 秒 burst 只存在于 AR11158 的一个 AIA 双通道窗口，不能自动外推到 AR11429 留出事件。

每条任务运行前必须检查 cadence、窗口长度、波段、空间分辨率和信噪比。不满足时应返回 `not_observable_with_current_data`，而不是“未检测到”或“需要更多同类文件”。

### 6.3 任务准备度需区分“缺数据”和“缺执行器”

当前 `requires_data` 同时表示缺少新观测、缺少派生量、缺少算法和缺少外部设施，导致系统过早给出 `needs_data`。

建议改为：

- `executable_now`
- `requires_executor`
- `requires_derived_product`
- `requires_new_observation`
- `external_facility`
- `human_review`
- `blocked_quality`

[default-services.ts](../packages/agents/src/scientific-loop/default-services.ts) 还直接把 `discriminatingOutcomes` 写入 `successCriteria`，其中常同时包含成功、失败和模糊结果，应拆成结构化 outcomes。

### 6.4 已执行覆盖与计划覆盖必须分开

[closure-gate.ts](../packages/agents/src/scientific-loop/closure-gate.ts) 把证据和计划任务引用的 prediction ID 合并为 `coveredPredictionIds`。这会让尚未执行的计划看起来像已验证内容。

至少拆成：

- `executedPredictionIds`
- `plannedPredictionIds`
- `validSupportPredictionIds`
- `contradictedPredictionIds`
- `unobservablePredictionIds`

闭环完整性可以参考计划覆盖，但科学支持只能参考已执行且通过证据门的覆盖。

### 6.5 置信度更新要依赖有效证据

目前 `confidenceBasis` 的审计轨迹是优点，但 0.50→0.53→0.56 的更新使用了被错误绑定或被 correction 否决的证据。应在证据裁决完成后再更新，并报告：先验、有效支持、矛盾、事件独立性、可观测覆盖和留出结果分别贡献多少。

## 7. 数据量决策

### 7.1 当前核心数据包

manifest 记录的核心包不是完整 10 GB，而是 **7,373,871,360 字节，即 7.374 GB（6.867 GiB）**，包含 704 个唯一资产：

| 观测窗             | 角色          | 资产数 |     大小 | 覆盖                                  |
| ------------------ | ------------- | -----: | -------: | ------------------------------------- |
| AR11158 background | 同区背景/反例 |    190 | 1.932 GB | AIA 94/131/171/193/211/335 + HMI LOS  |
| AR11158 target     | 发现事件      |    324 | 3.567 GB | 同上；另有一个 24 秒 AIA 双通道 burst |
| AR11429 target     | 跨活动区留出  |    190 | 1.875 GB | AIA 六通道 + HMI LOS                  |

预处理后的 NPZ/特征文件可以明显降低计算和传输成本，但它们仍来自同一原始 lineage，不能被计为新的独立事件或新证据来源。提交复现包应保留原始文件哈希、预处理参数、版本和派生产物映射。

### 7.2 现在是否立即补数据

**不建议立即大规模补。** 当前包足以完成闭环工程验证、背景对照、一个发现事件和一个跨活动区留出事件。先把第 5 节的分析能力做出来，能显著增加有效可观测量和方法家族，而无需增加 GB。

但是，系统自己的严格支持门要求至少 3 个独立目标事件和 3 个独立原始 lineage。当前只有两个目标事件，因此若目标是让某个假设有资格进入 `supported` 候选，最终仍需至少再补 **1 个独立目标事件**。按现有普通两小时六通道 AIA + HMI 窗口估算约增加 1.8–2.0 GB，使核心包达到约 9.2–9.4 GB。

这只是当前门槛的最低数量，不代表科学上充分。比赛演示建议按事件数而不是 GB 管理：

- 最低闭环：3 个目标事件 + 1 个同区背景/负对照；
- 更稳健的比赛验证：5–8 个目标事件，覆盖至少 3 个活动区，并配 2–3 个背景/负对照；
- 只有在波动诊断确实需要 Doppler 速度或非热展宽时，再定向加入 EIS/IRIS 光谱；
- 只有在磁剪切/自由能成为决定性预测时，再定向加入 HMI 矢量场，而不是无目的扩大 AIA 文件量。

按当前窗口规格，更稳健的数据集通常会落在约 13–20 GB 的量级；这是工程规划范围，不是官方规定，也不是支持结论的充分条件。

## 8. 推荐修复顺序与验收矩阵

| 顺序 | 修复项                          | 重跑验收                                                       |
| ---: | ------------------------------- | -------------------------------------------------------------- |
|    1 | 指标能力—预测合同               | 热变异执行器不能覆盖冷却时滞；不可检测预测明确返回不可检测原因 |
|    2 | correction 裁决层               | `error` 纠错后的证据不再进入有效支持和置信度更新               |
|    3 | 原子 EvidenceBundle 与事件隔离  | 所有角色对同一轮、同一事件引用相同 case、processing run 和指标 |
|    4 | 显式 case 路由与数据状态        | 多活动区输入不再被误判为数据缺失                               |
|    5 | 结论后置验证器                  | 零有效支持时不能排序机制，也不能出现软性支持措辞               |
|    6 | WCS + 冷却时滞 + 事件目录       | 现有六通道数据产生可审计的第二可观测家族和第二方法家族         |
|    7 | 沿环传播 + HMI 代理 + 耦合 null | 波动、重联和耦合假设分别拥有真正区分性的指标                   |
|    8 | 闭环覆盖和 readiness 重构       | 已执行、已支持、已反驳、计划中、不可观测五类状态一致           |
|    9 | 重跑四个 Qwen demo              | 基线、路由、留出和对抗用例全部通过，无跨事件污染和假覆盖       |
|   10 | 再增加第三目标事件              | 冻结所有阈值和参数后执行，禁止根据留出结果回调                 |

还应补充以下自动化测试：

- 指标能力与 prediction ID 不匹配时拒绝 `support`；
- 240 秒 cadence 对 1–5 分钟预测返回不可检测；
- 自由文本包含多个 NOAA 编号时能分别路由；
- AR11158 指标不能绑定 AR11429 processing run；
- correction veto 后证据门、置信度和结论同步变化；
- 计划任务不计入已执行覆盖；
- 零有效支持时自然语言结论不得比较机制优先级；
- 同一留出事件重复运行不能被计为新的独立 lineage。

## 9. 次要工程问题

本次停止本地服务时，托管进程实际都已停止，但 [stop-local.ps1](../scripts/stop-local.ps1) 在进程退出竞态下访问 `StartTime` 出现空值异常，并留下过期状态文件。应把进程获取、启动时间读取和停止操作放入带异常保护的单个过程，并在 `finally` 中清理状态文件。这不影响科学结果，但会损害一键复现体验。
