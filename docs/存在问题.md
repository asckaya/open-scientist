### 对“为什么还没有机制 supported”的判断

这不是单一故障。当前 13 个已处理事件中，DEM、冷却序列、热事件分布、矢量磁场等若干**诊断**可得到
`support`，但它们多为不同机制共享预测。机制 `supported` 还要求至少三个独立事件、至少两个可观测家族、
至少两个方法家族、完整预测覆盖、留出验证、定量区间、可审计溯源，并且没有有效机制级反例。
新增 EIS/NuSTAR 输入尚未转化成通过上述门禁的事件级派生证据，所以系统保持 `uncertain` 是目前正确结果，
不是应通过降低阈值修掉的结果。

## P0-1 统计功效通道在生产代码中不可达（验证体系最关键缺陷）

**问题**：`ValidationDetectability.adequate` 是淘汰门禁与反例搜索状态的核心判据，但生产代码中它**恒为 false**：

1. 预注册模板写死：`preregisteredLocalDetectability()`（default-services.ts:3221-3236）固定
   `alpha:0.05, targetPower:0.8, minimumMeaningfulEffect:0.5, minimumIndependentEventCount:3, adequate:false`。
2. 任务完成时再次强制：`localDiagnosticsAgent` 落任务结果时置 `adequate:false` 并注明"完成≠有功效"
   （default-services.ts:2669-2684）。
3. 全仓库 `adequate:true` 仅存在于测试 fixture（scientific-evidence-gate.test.ts:235）。
4. 不存在任何真实 power / MDE 计算：schema（scientific-loop.ts:252-302）定义了
   `achievedPower / minimumDetectableEffect` 字段并有 superRefine 一致性约束，但**没有任何生产代码填充它们**。

**影响链**（全部可从代码推出）：

```
adequate 恒 false
→ taskSupportsAdequateCounterexampleSearch()（evidence-gate.ts:186-199）恒 false
→ assessEliminationGate 的 decisive 条件（行 261-262）永不满足 → eliminated 不可达
→ assessCounterexampleSearch()（closure-gate.ts:27-86，行 63-65）把已尝试任务判为 underpowered
→ "adequately_tested_not_detected"（诚实阴性结果，schema:344-350 之一）不可表达
→ runDisposition 只能落在 deferred_underpowered / deferred_requires_data
→ closureStatus 恒为 partial，淘汰能力成为"测试里存在、生产中不可达"的死通道
```

**修复设计**：

1. 新增确定性功效评估器 `evaluateDetectability(diagnostic, preregistered, observed)`（建议放
   `evidence-gate.ts` 或独立 `detectability.ts`），按诊断类型定义检验统计量：
   - 区间型指标（相关/比率）：以 bootstrap/置换区间半宽反推 MDE，`achievedPower` 用正态近似
     `Power = Φ(|effect|/SE − z_{1−α/2})` 估计；
   - 计数型指标（通过案例数）：按二项精确功效表计算；
   - 输入全部来自已完成诊断的 `quantitativeResults`（点估计、区间、样本量/独立事件数），不引入新自由参数。
2. 判定规则保持预注册语义：`achievedPower ≥ targetPower` 且 `MDE ≤ minimumMeaningfulEffect`
   且 `independentEventCount ≥ minimumIndependentEventCount` 三者同时成立才置 `adequate=true`；
   `minimumMeaningfulEffect` 从全局 0.5 改为**按诊断类型预注册**（如冷却相关 r=0.3、Doppler 速度
   2 km/s、fluence 幂律斜率 0.5），写入 `buildRegisteredLocalDiagnosticTasks` 的每条 specification。
3. `localDiagnosticsAgent` 落任务结果时改为调用评估器回填 `detectability`（保留"完成≠有功效"语义：
   评估不通过仍为 false，但必须带 `achievedPower/MDE` 数值与理由）。
4. 新增单测：①功效充足的合成诊断 → adequate=true → eliminated 通路打通；②功效不足 → false 但带数值；
   ③superRefine 一致性（adequate=true 必须有 achievedPower/MDE）。

**验收**：local-grounded 两轮回归中至少一个反例搜索任务获得非 underpowered 的终态；
`assessEliminationGate` 的 reasons 在功效不足时给出量化缺口（"差多少事件/效应"）。

## P0-2 EIS"版本化标定"只是文本承诺，无代码强制

## P1-4 独立性判定完全依赖字符串相等，无交叉一致性审计

**证据**：`assessSupportGate` 的独立事件组/独立原始谱系直接对 `lineage.eventGroupId` 与
`rawDataFingerprint` 做去重计数（evidence-gate.ts:378-381）。

**问题**：两类完整性风险均无检测——
①同一 `rawDataFingerprint` 出现在不同 `eventGroupId`（事件组划分漂移，独立性被高估）；
②同一 `eventGroupId` 下出现多个本应同源的指纹（谱系漂移，独立性被高估）。

**修复设计**：新增 `auditIndependenceConsistency(records)`（建议 closure-gate.ts），在 C.verify 前
执行：构建 fingerprint→eventGroups、eventGroup→fingerprints 两个倒排索引，发现一对多即产生
`kind:'provenance'` 的 correction（复用 ScientificCorrectionSchema:484-497），把涉事记录降级为
`diagnostic_boundary` 等待复核；审计结果写入 closureReports。单测覆盖两类漂移各一例。

## P2-10 WCS 链未做差分自转补偿

**证据**：analyze_coronal_window.py 的重投影（`reproject_frame`，行 168）以 AIA 193 Å 参考网格
对齐，但多小时窗口内未施加太阳差分自转补偿；限制已在 limitations 披露（行 2590 一带）。

**修复设计**：在 `reduced_frame`（行 186）管线中按帧时刻相对参考时刻施加标准差分自转

A/B 对比输出配准残差统计。注意：版本升级会使全部派生缓存失效，首次重跑成本需预估。
