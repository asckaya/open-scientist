## 〇、定位声明：什么是创新点，什么不是

- **结构创新**：我们为"LLM 科学推理的可靠性"专门设计的**机制结构**——
  它们不是学术界的通用方法论本身，而是把方法论变成**在智能体循环中被机器
  强制执行、无法被模型措辞绕过**的具体结构。
- **不是创新点**：功效分析/预注册/序数等级等科学方法论本身（属于科学惯例）；
  代码重构与工程卫生（属于质量措施）。这些单独列出，不冒充创新。

## 一、六个结构创新（我们设计的独特机制）

### 创新 1 — 双门禁裁决结构：科学结论的全部收敛点是无状态纯函数

- **设计**：假设的 `supported / candidate / uncertain / eliminated` 只在两个
  纯函数（支持门禁七条件 / 淘汰门禁四条件）中计算，A→B→C→D 任何阶段的
  模型输出都无权改变判定；supported 时的结论措辞被系统覆写为有界模板
  （boundedConclusion），假设级伪概率 `confidence` 由 schema 强制为 null。
- **为什么算设计而非惯例**：一般 agent 工作流把"结论"交给 LLM 生成；
  本结构把"结论"降格为**对门禁输出状态的措辞封装**，越界即 correction。
- **代码锚点**：`evidence-gate.ts`（`assessSupportGate` / `assessEliminationGate`）；
  `scientific-graph.ts` C.verify / C.synthesize。
- **运行证据**：全部真实回归的终态判定与模型措辞无关；模型生成的
  机制贡献比例/概率式表述均被移除。

### 创新 2 — 能力契约：预测-执行器绑定的合法性与覆盖正确性分离

- **设计**：每个预测先经 DECISIVE/WEAK 两级观测量族规则解析出"决定性测量
  需求"，再与执行器的能力族求交——不具备该族测量能力的执行器**结构性
  不可认领**该预测，无论措辞多相似；复合预测合法分发到多个执行器。
- **为什么算设计**：把"哪台仪器能测什么"编码为可执行的契约表，而不是
  依赖提示词或模型自觉；这是针对 LLM 工具选择假覆盖问题的专属结构。
- **代码锚点**：`executor-capabilities.ts`（`predictionRequiredFamilies` /
  `executorSupportsPrediction` / `filterPredictionIdsByCapability`）。
- **测试锚点**：`executor-capabilities.test.ts`、`scientific-comprehensive-planning.test.ts`。

### 创新 3 — 独立性的机器审计：事件组 × 原始指纹双向倒排 + 需求词表合并

- **设计**：C.verify 前对全部证据构建 fingerprint→eventGroup 与
  eventGroup→fingerprint 双向倒排索引，任一方向出现"一对多"即判独立性
  高估，自动产生 provenance correction 并降级涉事记录；D.plan 的自由文本
  数据需求经受控词表归一（`canonicalValidationSourceId`），同义需求
  **合并覆盖而非简单删除**，留下审计记录。
- **为什么算设计**：独立性是门禁的根基，但一般实现只做计数；本结构把
  "计数的输入本身"纳入审计对象。
- **代码锚点**：`evidence-gate.ts` 的 `auditIndependenceConsistency`；
  `validation-source.ts`；`scientific-graph.ts` 语义合并。
- **测试锚点**：`scientific-plan-merge.test.ts`。

### 创新 4 — 功效门控的证伪通道："充分检验后的阴性"成为一等结局

- **设计**：每个证伪任务注册时绑定按诊断类型冻结的
  `targetPower / minimumMeaningfulEffect / 最小独立事件数`；完成时由
  `evaluateDetectability` 从已测置信区间按独立事件重建标准误（重复帧/重复
  处理只计一次）反推 `achievedPower / MDE`；只有功效达标者才能把"未检出"
  记为 `adequately_tested_not_detected`，不足者强制 `underpowered`，
  且候选级 `counterexampleSearchAdequate` 不允许由单任务达标外推。
- **为什么算设计**：功效分析是统计学惯例，但让它在 agent 循环中**由区间
  数据自动计算、并门控淘汰与诚实阴性两条通道**的结构是我们实现的。
- **代码锚点**：`detectability.ts`；`evidence-gate.ts` 的
  `taskSupportsAdequateCounterexampleSearch` 与淘汰门禁四条件。
- **运行证据**：`run-1787839551365`：`aia_94_131_relative_variability`
  achievedPower=1.0、MDE=0.0195≤0.2 → 一个证伪条件 `adequately_tested_not_detected`；
  同候选另一证伪条件仍 `underpowered` → `counterexampleSearchAdequate=false`。

### 创新 5 — 双闭环分离报告：流程完整性与科学充分性是两个独立指标

- **设计**：`workflowClosure`（所有假设已处置、无可执行遗留、无 unassessed
  漏分类）与 `closureStatus`（证据是否足以确证机制）分开计算与展示；
  无法分类的任务强制落 `external` + `unclassified_by_planner`，每个假设
  都有机器可读终局处置枚举（`accepted_bounded_process` /
  `deferred_requires_data` / `deferred_underpowered` / …）。
- **为什么算设计**：防止"流程跑完"被误写成"科学完成"——这是 LLM 系统
  常见的失败模式，本结构在 schema 层将其分离。
- **代码锚点**：`closure-gate.ts`（`assessScientificClosure` +
  `normalizeValidationReadiness`）。
- **运行证据**：全部回归终态 `workflowClosure=complete` 且
  `closureStatus=partial` 并存。

### 创新 6 — 科学边界随数据走：`mechanismEvidencePermitted` 的全链类型强制

- **设计**：辅助/正控产物的"不可用作机制证据"边界不写在文档里，而是
  从 Python 产物字段 → TS Zod 契约（`z.literal(false)`）→ 证据记录
  `unknown`/`diagnostic_boundary` → 门禁计数排除，逐层由类型系统强制；
  读取层强制 SHA-256 与 manifest 登记一致，功效不足的产物也以边界记录
  显性呈现（而非静默缺失）。
- **为什么算设计**：把"边界跟随数据、任何消费方都无法绕过"做成类型级
  结构，而不是提示词约定。
- **代码锚点**：`packages/schema/src/supplement-analysis.ts`；
  `packages/tools/src/coronal-data.ts` 的 `loadSupplementAnalysisDiagnostics`；
  `default-services.ts` 的 `supplementDiagnosticsAgent`。
- **运行证据**：`run-1787982672111` 中 10 条补充证据（EIS v2 14 项区间指标、
  NuSTAR v2 3 条 3σ 上限、3 条功效边界记录）进入证据层且不改变门禁计数；
  FPMA/FPMB 计数比 20.78 的异常如实披露。

### 附加-5（2026-08-29）：supported 不可达的根因诊断（v4 预处理升级副作用）

**现象**：8/28 回归（run-1787839551365）曾得到 1 条 `supported/strong`
（bounded_process_support，4 条 mechanism_discriminating 证据：4 独立事件、
3 观测量族、3 方法族、holdout、2/2 预测覆盖）；此后全部运行只有 `uncertain`。

**根因链（逐环验证）**：

1. v4 预处理（差分自转 wcs-roi-dem-v4）重建全部派生层 → 时序对齐变化 →
   事件目录与幂律拟合微移；
2. 三个 validation 案例的 fluence 诊断从 support 降为 unknown（预注册判据
   边缘性失败，数据如实回答）：
   - ar11082-cooling：阈值稳健性 persistence = 5/16 = 0.3125（判据 ≥1/3，差 1 个事件）；
   - ar11420-coronal-rain：幂律指数 CI 宽度 3.16（判据 ≤2.5）；
   - ar11850-loop-heating：CI 宽度 4.0（判据 ≤2.5）；
3. cohort 资格案例从 ≥3 降至 2（仅 ar11089-dem validation + ar11899 holdout）；
4. `cohortReadiness.status` 由 ready → insufficient → A 阶段 prompt 的
   cohort 候选分支不触发 → 模型不生成"所选跨事件样本"候选（或 scope 写成
   单区域自相矛盾）；
5. 无 validation/holdout 处理运行 → `cohortMechanismEvidence` 无输入 →
   0 条 mechanism_discriminating support → 门禁七条件全失败 → 永远 uncertain。

**本轮已完成的结构修复**（保证 cohort 声明出现时链路不再断）：

- A 阶段 scope 矛盾校正（`normalizeScopedImpulsiveStatement` 扩展：cohort
  statement 配单区域 scope 时统一校正，附 3 项单测）；
- D.plan holdout 兜底逐假设化（一个 holdout 绑给其他假设不再跳过 cohort
  假设的复测保障）。

**剩余修复选项（按诚信排序）**：

- A. 领域专家复核 v4 差分自转实现与事件目录变化是否物理合理（判据不放宽）；
- B. 补充更长窗口观测 → 事件数增加 → persistence/CI 自然改善后判据诚实通过；
- C. 接受现状：预注册判据下的 uncertain 是数据的诚实回答，不构成提交障碍。

### 附加-6（2026-08-29）：第 7 项实验——用满帧数据仍无法诚实达成 fluence support

按验收清单第 7 项做了"用满数据"实验：`MAX_SERIES_FRAMES` 96→240（v5 =
wcs-roi-dem-v5，全帧利用），对 ar11420-coronal-rain（validation）重跑完整
冻结链（220 帧 AIA 全配准、差分自转 220 帧应用、0 失败）。结果：

- persistence 判据修复确认（0.571 ✓ stable ✓）；
- 但幂律指数 CI 宽度 **3.156 仍超 2.5 判据**。在这个固定观测时间窗内，
  96→220 帧没有改变 23 个事件的冻结目录或 bootstrap 区间，因此可以排除
  “96 帧上限造成当前 CI 过宽”，但不能据此声称所有更长观测窗的区间都与帧数无关。
  真正决定区间能否收窄的是按预注册选择获得的独立事件数及其尾部分布，而不是单纯重复
  采样同一个已冻结时间窗。

**最终定论**：fluence support 在当前观测数据形态下诚实不可达；
`cohortReadiness=insufficient` 是预注册判据的正确输出；supported 需要
**新的、事先登记选择规则的独立/更长观测窗**来增加事件样本，而非管线调整。
不能在看到尾部结果后只挑“强尾部事件”，也不能保证新增 1–2 GB 后必然通过；新增数据

### 附加-8（2026-08-30）：闭环不依赖人工参与 + 可选人机协同通道（human-in-the-loop）

**设计不变量（双重要求）**：

1. **闭环不等人为先**。科学闭环没有任何路径需要人工输入才能完成：
   `human_review` 任务只产生 `deferred_external_validation` 处置（closure-gate.ts），
   不计入 `executableNowTaskIds`，`workflowClosure` 不因其存在而受阻；
   默认 `humanGate: 'off'` 时运行全程无人工等待。该不变量由
   `scientific-human-channel.test.ts`（"planned human_review task + 无人工通道 →
   workflowClosure=complete"）锁定为回归。
2. **人工参与是可选交互面，不是证据来源**。人工可以暂停、注入转向消息、
   应答审批门——但**不能**写入证据、改写支持/淘汰门禁裁决或假设状态。
   转向文本在模型路径只作为候选生成的侧重参考（prompt 块明示"不可改变门禁裁决"），
   在 local-grounded 确定性路径只登记不消费（保持可复现）。

**机制（packages/agents/src/scientific-loop/human-channel.ts + apps/api 控制面）**：

| 通道                    | API                                | 循环内挂点             | 语义                                                                                               |
| ----------------------- | ---------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------- |
| 转向（steer/follow-up） | `POST /runs/:id/steer`             | A.generate 入口 drain  | 下一轮候选生成的侧重参考；进 `result.humanSteering` 审计                                           |
| 暂停/恢复               | `POST /runs/:id/pause`、`/unpause` | 每个节点边界协作式检查 | 不打断进行中的智能体步骤；`/stop` 仍可强制终止                                                     |
| 审批门（plan_review）   | `POST /runs/:id/approve`           | D.route 续轮决策处     | 仅决定"是否继续下一轮"；拒绝 → `human_halted_at_plan_review`；超时/中止 fail-open 自动继续并留审计 |

启动配置：`POST /runs` 新增 `humanGate: 'off'|'plan_review'`（默认 off）与
`humanGateTimeoutMs`（fail-open 上限，默认 5 分钟）；审批门**永不**卡死运行。

**验收**：新增 11 项测试（转向注入/审计、暂停恢复、门禁批准继续、拒绝终止、

## 五、赛题必要性映射：五个缺口各自解锁哪条证伪条件

> 依据：`run-1787978539877` 中模型为每条假设生成的证伪条件与门禁未满足项。
> 结论：每个缺口都绑定一条**已生成的、当前不可检验**的证伪条件——补齐它 =
> 把该条件从"无法检验"变为"可检验"，而不是泛泛的天文学愿望。

| 假设（模型生成） | 证伪条件（节选）                                           | 当前为何不可检验                                                      | 解锁所需缺口 |
| ---------------- | ---------------------------------------------------------- | --------------------------------------------------------------------- | ------------ |
| 波动耗散         | "非热展宽不随高度变化或与强度变化无相位关系，排除波能耗散" | 光谱族预测只有 AR11899 单事件 + AR11890 单 raster，无跨事件区间       | ①            |
| 波动耗散         | （支持侧）能流是否闭合辐射+传导损失                        | 无人工核验环路径，密度/传播/阻尼无法沿路径提取                        | ②            |
| 纳耀斑/重联      | "热事件与磁演化无时序相关…排除重联驱动"（能量预算侧）      | SHARP 代理只是代理；无自由能预算与磁拓扑，"重联位置/能量够不够"不可判 | ③            |
| 纳耀斑/重联      | "辐射能分布指数 γ<2 或无幂律特征"的硬 X 射线侧             | 计数率上限不是物理流量；无法约束非热尾参数空间                        | ④            |
| 全部候选         | 机制间比较（而非只测共同预测）                             | 无观测几何匹配的合成观测，无法做"哪个机制的合成签名匹配观测统计"      | ⑤            |

补齐后的判定变化：①+④ → 光谱/HXR 族预测获得跨事件区间，支持门禁的
"≥3 独立事件、≥2 观测量族、≥2 方法族"可被真实满足或如实否定；②③ →
波动/重联假设各获得一条**功效充分**的能流/能量预算证伪通道（`underpowered`
升格为可判定）；⑤ → 从排除法升级为模型比较。在此之前，过程层结论
（bounded_process_support）与 `requires_data` 登记就是系统的正确终态。
